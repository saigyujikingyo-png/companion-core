Scope: after IF8's authorized PR/CI/review/merge closure, implement two explicit bounded capacity operations in one new independent worktree. Root owns architecture; one Astra xhigh author owns code/tests/docs until freeze; reviewers read only; actual GPT-6.1 Sol performs setup/mechanical verification. ## Outcomes and nonnegotiable invariants

1. Physically repack a validated Store image on a private disposable RAM connection, and activate it as a fresh encrypted target generation using the existing exact authority transaction protocol. Retain all committed application rows, permanent logical PKs, ingress payload bindings, jobs/results, dependency closure, revocations with original reason/time, scopes/epochs, FTS content, fanout journals/consumers/projection/progress and SQLite AUTOINCREMENT high-water state. This reduces page fragmentation/free extent; it does not discard history or create infinite capacity.
2. Introduce explicit storageProfile `blocks-br4-safety-br4-v1`. It losslessly encodes each complete Safety v1 snapshot before frame encryption, reducing repeated header bytes. Logical Safety remains v1 with all fields and array order; 8192 ingress and maxCalls<=32 stay unchanged. No refund, retry, UNKNOWN resolution, key/fingerprint weakening, delivery-ID reuse, feedback reset or omission. Existing M2/v2 and two old v3 profiles/golden behavior stay unchanged.
3. Long-term exact indices are permanent under current semantics. Physical index packing is in scope through Store repack; deleting or probabilistically replacing entries, external archive/router, raising limits, unlimited retention or full hot/cold query architecture are not implemented by this slice. Document those remaining requirements explicitly. Side I17 remains DESIGN_ONLY, not part of this implementation.

## Safety carrier and profile upgrade

- Use a closed versioned Safety carrier in the new profile's frame header, with explicit codec, decoded JSON bytes/digest and canonical base64 for br4 data (or a comparably simple bounded representation after reviewer concurrence). An inline/raw-JSON carrier is allowed when its complete serialized carrier is smaller; compare full descriptor+encoding overhead, not compressed payload alone. Both carry complete exact Safety v1 JSON; no field normalization or array reordering.
- Each decoded Safety JSON is bounded at4MiB; encoded/carrier is bounded by the existing4MiB frame-header limit. Do not enlarge FRAME_LIMIT, MANIFEST_LIMIT, MAX_CHAIN16 or MAX_REPLAY_BYTES64MiB. Reject wrong shape/version/identity, count, scalar type, malformed JSON/UTF8, noncanonical base64, wrong lengths/hash, truncation, concatenated/trailing compressed input and overexpansion. No fallback to empty Safety, prior frame, uncompressed interpretation or unused request on corruption.
- Validate full original Safety via the existing validator after unpack. Business APIs continue receiving normalized Safety v1. Preserve all terminal states, delivery IDs, reserved flags, feedbackConsumed, lastSourceRef/acknowledged ID/wall, identity and maxCalls exactly. Current rights/Store revocation state is not changed by compressing Safety.
- The profile is bound by marker, head, identity and AEAD AAD. Explicit upgradeStorage supports existing v2->v3 behavior and a narrowly allowed old v3 profile->new packed profile transition, in a disjoint new target under exact oldHead CAS; no silent reinterpretation or downgrade. Keep stable keys/epochs per original protocol, ownerEpoch++, legacy proof and receipt request digest. Normal compaction must not change profile. Existing unrecognized-profile rejection remains.
- For the new profile, replay decodedBytes must include image patch rawLength PLUS decoded Safety bytes for every required frame, on both encoder baseline and decoder. Refuse oversized chain before further decompression/allocation, and emit an earlier base when needed. Old-profile budget/golden semantics remain. Backup/restore/rekey/compaction/reconcile and legacy import must remain self-contained and use the normalized decoder; no external cold sidecar is added.

The next true archival design must authenticate immutable history segments in the active head and maintain exact permanent request/delivery/Store/legacy indices, with shared transaction/fencing and complete backup/rekey/cutover closure. Missing history is corruption, never absence. No finite fixed-size exact map can remember arbitrary unbounded distinct IDs; quotas/retention policies must remain explicit rather than silently forgetting consumed operations. This IF9 slice recovers avoidable physical overhead while preserving that requirement.
