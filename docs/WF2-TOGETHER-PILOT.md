# WF2 .7 Together first-four research pilot

Current failure-output versions are specified in [WF2 failure diagnostics](WF2-FAILURE-DIAGNOSTICS.md). The transport versions below retain the earlier protocol snapshot; provider requests and profile semantics are unchanged.

This is a new, separately admitted `wf1-campaign/0.7` experiment. The previous DeepSeek stable named-data .6 actual attempt stopped at its first seal: one DeepSeek call, zero Together calls, native-invalid arguments, no seal/plan/qualified data. That negative result and every earlier consumed campaign remain retained. Nothing is repaired, retried, regraded or automatically routed to this pilot. The old .3/.4/.5 and two .6 profiles retain their request semantics and limits.

## Fixed scope and provider protocol

The only provider is Together, with the real model ID `openai/gpt-oss-120b`. Three independent bootstrap contexts author 12 sealed cases, the full 16-family plan with its eight predeclared pair IDs, and a separate rubric. Four candidate contexts and four fresh review contexts then process exactly the plan's first four families. This is 11 Together calls, zero DeepSeek calls, no comparison calls and no auxiliary calls. The sealed content is never provided to plan, candidate or review calls.

The developer message requests JSON and carries the complete schema; `response_format` is `{type: "json_schema", json_schema: {name, schema}}` with the identical schema. `reasoning_effort` is fixed to `medium` by pilot policy `wf2-together-first4/4`; callers cannot select another effort. Seal/plan completion limits are 8,192; rubric/candidate/review limits are 4,096. The fixed-slot schema uses standard `$defs` and `#/$defs/` references in an acyclic `bounded-depth6/1` dialect; all substantive IDs, roots, questions, rubrics and answers are model authored. The fixed object slots project in a predetermined order to the original local contracts without normalization, defaults or lost fields. The original final bytes are retained. No function is executed and no tool-result turn is appended.

Policy `/4` retains the source-only schema compiler introduced in `wf2-together-first4/2`: `expression1` is the original leaf, and `expression2` through `expression6` each allow that shared leaf or the original binary expression with both children referencing the previous level. Original expression references now point to `expression6`; the recursive definition is removed. Other definitions, required fields, slots and instruction text are unchanged. The developer message and `response_format` carry identical compiled schemas. This preserves the structural domain through six levels; the original local 31-node, 128-bit, arithmetic, oracle and source gates still apply. No model output is normalized or repaired.

The schema, endpoint, model, operation, completion limit, codec and profile are bound to the complete request before durable consume. DeepSeek and comparison operations are refused before dispatch. The .7 profile digest is the only trusted selector for the larger Together call count; old profile limits remain unchanged. Provider credentials have the same closed two-key shape, but .7 requires `deepseek: null` and a nonempty Together key. Other admitted production profiles still require their original credentials.

The fixed reservation uses 18,432 input tokens per call and frozen declared prices. At input 150,000 and completion 600,000 microUSD per million tokens, the total reservation is `2 × 7680 + 9 × 5223 = 62367` microUSD, under the independent 100,000 microUSD Together/total cap. This is an estimate, not an invoice guarantee. Unknown usage, transport ambiguity, authority loss, time or budget violations stop the run. There is no adaptive limit increase or replacement question.

Every request still has a 16,384-byte ceiling. `preflightPilotBootstrap(objective)` constructs all three exact bootstrap bodies without credentials, artifacts, ledger creation or API calls. A 2,048-byte public ASCII objective produces seal 12,723, plan 15,288 and rubric 5,940 bytes. An 8,192-byte objective may satisfy the objective field limit yet exceed the independent whole-request limit and is refused before admission. The actual launcher must preflight the verbatim objective; it must not truncate or rewrite it.

## Acceptance and provenance

The original strict JSON, closed local schema, rational-only domain, exact rational oracle, source exclusion, known-root and formal fingerprint gates remain. Leaf bounds remain 128 bits; computed targets are not incorrectly limited to leaf size. All 16 planned families must pass the original plan contract and have distinct supplied roots and formal fingerprints, even though 12 are not generated.

For original content authored in this campaign with no known content ancestor, the instruction uses `wf2.seal.original.*` and `wf2.plan.original.*` as separate naming domains. Every known inherited ID must remain exact across roles: no prefixing, renaming or false original claim. Candidate roots come directly from the plan. These are generation instructions, not a schema prefix requirement or output transformation. Same inherited roots still block; the same formal input under another namespace still blocks. Distinct declared roots cannot prove that numeric or template derivatives have no shared actual ancestry. The boundary remains `NOT_PROVEN_BEYOND_SUPPLIED_ANCESTRY`.

All first four candidates must pass every gate and receive a fresh-context `CLEAR` model review. A single failure stops the pilot with no repair or retry. The teacher and reviewer are the same model in isolated role contexts: `MODEL_REVIEW_ONLY`, not an independent model or a DeepSeek max judge. Chinese affective quality, PeerBench, Student inference/training and publication remain outside this experiment.

Only after all 11 successful, known-usage calls may the worker freeze `private-pilot-manifest`, version `wf2-private-pilot-manifest/1`. It explicitly carries `scope: PILOT_ONLY`, `remainingFamilies: NOT_RUN`, `pairedComparison: NOT_RUN`, and `reviewClass: MODEL_REVIEW_ONLY`. Its exact family set must equal plan positions 01–04, with four unique projections, three train rows and one dev row. An arbitrary other valid 3/1 set, an old 16-row manifest, duplicates, missing rows or changed roots/splits do not qualify. This does not claim completion of the original 16-plus-eight experiment.

## Transport compatibility and diagnostics

Only `message.content` supplies final data. Reasoning, choice text, prompts and warnings are retained only in raw custody. The new protocol permits optional Together root `prompt`/`warnings` and choice `text`/`seed`/`top_logprobs` with explicit types; unknown keys and wrong types reject. `seed` may be absent or `null`, or a signed safe integer from `-9007199254740991` through `9007199254740991`; negative zero, fractions and other types still reject. Nullable `seed` compatibility follows the observed public Together probe response; the official documentation has not confirmed a nullable guarantee. `seed` remains raw-only and never supplies final data. Older provider envelope lanes are unchanged.

This request does not enable echo or logprobs. The existing strict outer parser still rejects noninteger numeric tokens, including a noninteger optional logprob, as `ENVELOPE_WF1_NUMBER`. That is a limitation of this bounded profile, not proof that Together returned invalid native JSON. No generic float parser is introduced.

After final bytes are stored, .7 alone strictly parses and requires an object before reporting provider completion. Rejections use the closed `FINAL_NATIVE_JSON_INVALID`, `FINAL_WF1_JSON`, `FINAL_WF1_NUMBER`, `FINAL_WF1_DUPLICATE_KEY`, `FINAL_WF1_JSON_LIMIT`, `FINAL_WF1_UNICODE` or `FINAL_ROOT_NOT_OBJECT` codes. Native parsing is diagnostic only after strict rejection: its result is discarded and never used as fallback. Unexpected diagnostic errors remain `UNKNOWN`. Existing envelope/storage/transport codes retain their meanings. The code describes the latest settled attempt, not the quality of every earlier candidate; stale/pending observations remain unknown.

## Trusted interfaces and cold verification

`wf2-teacher-bind/2` and `wf2-teacher-inspect/2` retain their closed input fields and storage binding. The new spec selects .7 explicitly. The actual Windows launcher binds all new text/candidate/sealed/manifest data below the user's D training root; Core accepts only an explicit portable approved root and strict real-path descendant. Keys and independent authority remain outside that tree. No C fallback or old-data migration occurs.

Live .7 metadata adds one `profile` object: `{version: "wf2-teacher-metadata/2", campaignSchema: "wf1-campaign/0.7", profileDigest, scope: "PILOT_ONLY", remainingFamilies: "NOT_RUN", pairedComparison: "NOT_RUN", reviewClass: "MODEL_REVIEW_ONLY"}`. The trusted bridge must pass the exact frozen `metadataProfileDigest`; the default validator rejects this shape and does not expand its old Together-eight limit. This profile is included in the completion digest and receipt. DSH still receives only closed operation/state acknowledgements, never metadata, paths, capability, keys or bootstrap.

Use the separate `--inspect-pilot` CLI for .7. Success is `wf2-teacher-inspection/3`, the existing inspection/2 fields plus the exact `profile` object; refusal is `{version: "wf2-teacher-inspection/3", status: "REFUSED", code, responseFailureCode: "UNKNOWN", automaticResume: false}`. The original `--inspect` remains inspection/2 and rejects .7. The trusted imported inspection function selects its output version from the validated spec.

Cold inspection authenticates source/spec/head and the HMAC ledger without provider credentials or resume. It reports `RECORDED_CLAIMS_ONLY`. When completed retention is currently permitted, it reads only the train plan and pilot manifest, reruns the original 16-family contract and verifies the exact first-four set, roots, split, oracle, exclusions and uniqueness. It never reads sealed content. Failed/revoked campaigns expose authenticated recorded counts and diagnostic enums only. Manifest verification is distinct from recorded counters, and actual invoice remains unknown.

The earlier nullable-seed source change has a new worker build digest and requires a separately admitted actual run. It does not change the request, schema or profile digest, and does not regrade the original public probe or any previous negative campaign.

The historical policy `/1` to `/2` transition changed only the two seal/plan schema copies; its other request bytes and all .3–.6 profiles were unchanged. Policy `/3` changed only the fixed `reasoning_effort` field from `low` to `high`; current policy `/4` changes that field from `high` to `medium` in all five operations. The bounded-depth6 schemas and schema digests, instruction text, completion caps, call counts and cost reservation remain unchanged. Profile and worker build digests change, and the current reader rejects prior .7 specs and high/low-effort bodies before dispatch. Old freezes, source archives, original runs and negative public probes remain unchanged and are not regraded.

The prior low-effort policy `/2` actual attempt stopped at the first sealed exact-oracle gate with zero qualified rows. The subsequent high-effort attempt stopped after one Together call with `INCOMPLETE_FINAL`: its completion budget was 8,192 tokens, including 8,190 reasoning tokens, with zero qualified rows. Both negative attempts remain retained without replay or regrading. Policy `/4` is one separately admitted medium-effort experiment; it does not establish target correctness. Targets remain model authored and must pass the original exact oracle; no label substitution, retry, adaptive cap increase or relaxation of quality gates is introduced. If this medium attempt also fails, this batch is delivered as `PARTIAL` with zero qualified training delivery, and the original teaching objective remains open for a separate research task.
