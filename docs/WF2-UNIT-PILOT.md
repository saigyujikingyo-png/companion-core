# WF2 .8 cross-model unit pilot

This is a new, explicitly admitted `wf1-campaign/0.8` experiment. It plans four new sealed cases and four teaching families, then attempts four qualified rows (three train, one dev). It does not complete or regrade the earlier 12-case/16-family/8-pair campaign. The earlier `.3`–`.7` request profiles and bodies remain unchanged. Actual `.8` provider execution is separately admitted; synthetic success is not qualified real-data delivery.

The frozen schedule is four `seal` calls, four `plan` calls, one `rubric` call, then `candidate`/`review` for each of four slots. Slots are source-owned indices 0–3. Attempt IDs are `seal:unit0` through `seal:unit3`, `plan:unit0` through `plan:unit3`, `rubric`, then each `candidate:unitN`/`review:unitN`. The consumed attempt, request binding, exact request bytes, operation and unit index must agree. Candidate and review family IDs must match that slot in the frozen plan. A consumed, pending, unknown or failed request is never retried or resumed.

| Role | Provider / model | Calls | Per-call completion cap | Fixed mode |
|---|---|---:|---:|---|
| Seal, plan, rubric, target author | Together `openai/gpt-oss-120b` | 13 | 4096 | `reasoning_effort: medium`, native JSON schema |
| Reviewer | DeepSeek `deepseek-flash` | 4 | 8192 | `thinking: {type: enabled}`, `reasoning_effort: high`, native JSON object |

Every call reserves 18,432 input tokens. Frozen declared rates are Together 150,000/600,000 and DeepSeek 300,000/1,200,000 micro-USD per million input/completion tokens. Reservations are 13 × 5,223 + 4 × 15,360 = **129,339 micro-USD**, with 100,000 per-provider and 150,000 total ceilings. These are declared pricing estimates, not an invoice. The DeepSeek alias is not an immutable model snapshot. No tools, fallback, additional format probe or automatic repair is used. DeepSeek JSON-object mode does not itself enforce the local review schema; strict lexical, closed-field and local protocol validation still apply.

The preregistered slot curriculum uses root operations `add`, `sub`, `mul`, `div`, in order. Seal expressions have exact depth 2; plan expressions have exact depth 3. Finite DAG schemas and local validation enforce these requirements while retaining the original 31-node, 6-level, 128-bit leaf, 4096-bit intermediate and no-zero-divisor gates. Models author operands, suboperations, identifiers, roots, text and targets. Plan splits are also model-declared and checked against train/train/train/dev; the host never fills or repairs them.

Each new slot has a distinct suggested ID namespace and original-content root namespace. Known inherited roots must retain their exact IDs, regardless of slot. Namespaces avoid address collisions and do not establish independence; cumulative ID, root and formal-fingerprint checks remain mandatory. Supplied ancestry and exact fingerprints cannot establish independence from unknown pretraining material.

Each valid unit is privately persisted before the next slot. The aggregate seal reference appears only after all four sealed cases pass their exact target oracle and cumulative checks. The plan is a new `wf2-unit-plan/1` array of four complete `wf2-plan-unit/1` records, retaining every model-authored plan text; no host-written global plan or paired-ID list is invented. Its aggregate reference appears only after all four units pass. A partial set remains consumed private evidence, never a new run or a completed plan.

Each candidate receives only its own plan text and formal input. The rubric uses the original authorized objective in a fresh context and sees no seal or plan output. Each DeepSeek review sees only the current sample and the rubric, plus fixed public control instructions. It must independently recompute the formal input and compare the supplied target; its illustrative JSON format does not prescribe a verdict. Neither candidate nor review receives sealed cases. The label provenance is `MODEL_AUTHORED`; the review is `MODEL_REVIEW_ONLY` with topology `CROSS_MODEL`, not an independent truth or training-ancestry proof. Exact oracle, source exclusion and deduplication remain hard gates.

Completion requires exactly 17 settled calls with known usage, four accepted seal-unit references, four accepted plan-unit references, and four qualified Together candidates with the corresponding DeepSeek reviews. The new private manifest records both provider/model bindings and requires exactly four unique plan members, three train/one dev. Cold verification recomputes target oracles and checks the slot, attempt ID, family ID, request binding, provider/model and manifest membership. It does not read sealed payloads. Revoked or incomplete histories remain `RECORDED_CLAIMS_ONLY` with no manifest admission or automatic resume.

The existing `wf2-teacher-bind/2` and `wf2-teacher-inspect/2` bootstrap fields remain closed; `.8` requires both provider credentials through the trusted private pipe. `unitMetadataProfile()` is metadata version 3 and declares `.8`, `UNIT_PILOT_ONLY`, four sealed/planned families, `MODEL_REVIEW_ONLY`, `CROSS_MODEL`, and `MODEL_AUTHORED`. Only this profile adds actual `units: {sealed, planned}` counts to safe metadata: validated persisted reference counts 0–4, or both null when stale. Completed metadata additionally requires T13/DS4, four qualified candidates, zero unknown usage, units 4/4 and a frozen manifest. Older metadata does not accept the new field or limits.

The worker description is version 5, with explicit unit profile/limits and `--inspect-units`; unit cold output is `wf2-teacher-inspection/6`. The imported `inspectTeacherCampaign` selects that version only from an admitted `.8` spec. Older inspect CLI routes reject `.8`. Stopped events and bridge receipts remain the explicitly versioned `/3` interfaces. A captured `.8` failure uses `wf2-failure-diagnostic/2`, adding only the trusted bounded `unitIndex` (null for rubric or aggregate gates); stale/missing attribution remains unknown. See [failure diagnostics](WF2-FAILURE-DIAGNOSTICS.md).

The scoped synthetic tests cover schedule/body refusal before consume, curricula and preserved texts, every main failure stage, duplicate identities and roots, source exclusion, unknown review usage, pause/revoke with late responses, and the complete private worker → bridge → separate cold-reader path. The successful fixture checks four unique rows and rejects a wrong review-family binding even when all targets are otherwise valid. This source slice does not invoke a real Harness or provider, train a Student, or publish private artifacts.

Author validation of the combined source: one serial synthetic suite passed 978/978, strict TypeScript passed, and transpiled runtime closures matched their declared lists (teacher 22, legacy 19, format 17 modules). Independent final source and carrier review passed. The [actual run](WF2-VALIDATION.md#current-8-result--stopped-no-frozen-dataset) stopped after T11/DS1 at the second candidate's exact oracle: seal/plan 4/4, qualified candidate 1, quarantine 1, no frozen manifest. Cold inspection and duplicate refusal passed; original failures remain unchanged. Commit-specific cross-platform CI remains a separate PR check.
