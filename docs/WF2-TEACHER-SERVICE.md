# WF2 teacher control service

This slice implements a private control boundary, a deterministic DSH scheduler, and versioned trusted teacher bootstraps. The independent 0.4 actual campaign stopped at its first seal call: known usage was 1,492 input and 1,277 completion tokens, no Together call and no qualified data. Its native final failed native JSON parsing as well as the strict parser (`WF1_JSON`); the retained diagnosis does not identify a specific character or establish truncation. The separately admitted [0.5 rational data-function protocol](WF2-STRICT-DATA.md) first stopped because its closed response decoder rejected the provider's additional `index: 0` field before parsing arguments. Compatibility/2 crossed extraction but stopped on authenticated `CASES_CARDINALITY`; both consumed failures remain preserved. The new [0.6 fixed-slot protocol](WF2-FIXED-SLOTS.md) awaits independent runtime acceptance. The two independent format probes also retain their negative results; no earlier output is regraded.

The official DSH application plugin runs in an isolated empty-bundle profile and requires the absence of LLM, agent, session, title and compaction services. It uses no conversational prompt or SDK follow-up. Its only outgoing messages are the closed operations `status`, `start`, `pause`, and `cancel`, identified by bounded request IDs on one dedicated anonymous pipe. DSH receives no provider credential, custody key, random service token, user objective, runtime path, artifact reference or teaching material. The trusted parent validates each DSH message and adds the random capability in RAM before sending it on the separately bound teacher pipe. Those raw pipe lines are never audit or session content.

`TeacherControlService` accepts one already durably admitted `BoundTeachingRun`. It cannot create, reopen, resume or switch a campaign. READY requires an active zero-call binding. The trusted production worker must have completed fresh source/profile/authority checks and durable admission before constructing this service. A synchronous start-consumed flag prevents concurrent or repeated starts, while the existing teaching worker remains responsible for each durable provider-call consumption. Reusing a request ID for another operation is rejected. The request table is capped at 64 IDs; terminal controls remain available even when status requests have filled it. Pause is permanent for this service; a later cancel upgrades its external authority to revoked while closing the underlying run only once.

An unexpected owner-pipe EOF revokes current authority and aborts local work, including when a paused service later loses its owner. Late success cannot replace the terminal decision. Normal completion uses a different handshake: the trusted parent validates and durably records the completed metadata, then sends a private completion acknowledgement. Only a completed service accepts that acknowledgement; the subsequent normal EOF closes it without withdrawing retained artifacts. No DSH-facing operation can acknowledge completion. Retention does not grant Student training permission.

The ledger stays open between logical completion and acknowledgement, so status and acknowledgement recheck current authority. The acknowledgement binds the exact canonical safe-metadata digest issued for that completion; an authority or metadata change before acknowledgement refuses it and revokes the unfinished ownership. After acknowledged closure, this process no longer reports cached totals as current authority.

The production entrypoint is `node src/wf2-teacher-worker.ts`; `--describe` publishes its complete runtime-source digest, profile digest and closed bootstrap fields. The trusted launcher privately supplies a new runtime root, separate host-authority path, null expected head, 0.4 spec, custody key, verbatim objective, fixed-provider credentials and random control capability over one anonymous stdin. No path, credential, profile or provider route can be selected through DSH. Durable admission must finish before READY. The old `wf1-worker.ts` explicitly accepts only 0.3. Every current worker digest includes the new transitive request-policy dependency; historical probes are inspected through their retained archived source, not silently rebound to current bytes.

`runTeacherBridge` accepts trusted deployment callbacks for the two pinned child programs. Those callbacks belong to the launcher, not the DSH API; deployment must pin executable/source identities, isolate the DSH home and environment, and privately inject the teacher bootstrap. The bridge consumes its own once marker before starting a child and never respawns either child. A normally stopped campaign also produces an allowlisted terminal metadata snapshot and fixed reason, fsynced before owner withdrawal. Unknown authority or commit state has null totals. The final bridge receipt labels saved metadata as `RECORDED_TERMINAL_SNAPSHOT_NOT_LIVE`, retains known versus unknown usage, and separately records actual child closure. A negative receipt is not a completion acknowledgement or a data-quality pass.

The separate trusted administrative command `node src/wf2-teacher-worker.ts --inspect` reads one JSON document to EOF with exactly `version: "wf2-teacher-inspect/1"`, `runtimeRoot`, `authorityPath`, `expectedHead`, `spec`, and `custodyKeyBase64`. It accepts no provider credential or objective. It binds the current worker build, complete spec, supplied head and authenticated HMAC ledger, and reports only `RECORDED_CLAIMS_ONLY`: calls and known/unknown usage by provider, upward estimated usage cost, retained reservation, qualified/quarantined counts, recorded unique-manifest rows and invoice UNKNOWN. It cannot create missing owner state, recover journals, resume or dispatch a provider call.

Only a recorded COMPLETED campaign whose current host remains ACTIVE with retention permission can read back its train manifest and frozen train plan. The inspector never reads sealed artifacts; it internally checks the manifest's closed rows, exact typed-target oracle, qualified-candidate and source-exclusion commitments, unique projection fingerprints and split counts. Each row's family, roots, split and full formal input must exactly match the validated frozen plan. It outputs counts and enums only. Missing or invalid manifest material is `INVALID_OR_UNAVAILABLE`; a failed or revoked campaign is `NOT_READ`. The inspector rechecks authority and head after verification. This readback is still a retained observation, not fresh training authorization. A synthetic check exercised it in a separate real process after making custody artifacts unavailable and verified that runtime and authority file bytes stayed unchanged; altered split and roots are separately rejected.

Service replies use a closed metadata schema. Invalid or stale metadata becomes unknown totals, never zero calls. The service explicitly reports remote cancellation as unknown and raw-work closure as not established. Logical completion, local abort, direct-child exit and full process-tree cleanup are different facts; the parent must observe real child close and record timeout/forced/unknown cleanup separately.

The synthetic worker imports no provider. Local tests use separate real Node children for plugin framing and the fake bound service; they do not count as native DSH acceptance. The separate CI workflow keeps the existing four Core matrix jobs unchanged and adds Windows x64, Ubuntu x64 and macOS 15 arm64 native scheduler smoke. It installs only the exact official `deepseek-harness-runtime-bin==0.2.1rc2` wheel into a fresh runner-TEMP venv with SHA256 enforcement and no dependencies, then obtains the real executable through `deepseek_harness_runtime.bundled_runtime_path()`. Installed Windows Desktop `0.2.1-rc.3` remains a distinct carrier and evidence row. The smoke's source has zero provider calls; it does not claim an OS-enforced network firewall.

The smoke controller binds both real child close results, validated completion acknowledgement and the plugin hash into a safe receipt. It stops at the first protocol error, bounds stdout/stderr and applies a 20-second request deadline followed by a bounded hard cleanup. An unobserved close is failure, even if a kill request was issued. The receipt is printed in the CI log and retained in a fresh TEMP directory; it never contains the random capability or bootstrap.

The first native Desktop rc3 scheduler attempt exited both children without dispatching any operation and is retained as a failure, not a startup pass. The plugin had incorrectly executed its lifecycle cleanup inside the Cordis effect registration callback. The corrected callback returns a disposer; the focused fixture now executes the effect factory. A second independent attempt dispatched status/start and acknowledged completion but timed out during closure; it also remains a failure. The final handshake writes the settled frame, ends both already-acknowledged input pipes, and closes the plugin's owned stdin before DSH's dispose-and-exit-code shutdown. The third independent native rc3 attempt passed: two operations, completion acknowledgement, both real child exits 0, no forced cleanup, 1.49 seconds and zero model/provider calls. These are separate once records. The three rc2 cross-platform CI jobs remain pending; the independent actual 0.4 result is the negative seal result above.

The formal-pilot admission decision is explicit. Format profile/1 passed native and strict JSON for six cases but failed all six exact echoes. Profile/2 passed both parsers for six and exact echo for five; one field's value equalled the expected value's NFC form and differed by one UTF-16 code unit. This observation does not prove a provider-internal normalization step, general Unicode preservation, or correct natural-language teaching. Both probes remain `NOT_PASSED`; no third echo probe, normalization, target extraction or repair is admitted.

For this different task, the earlier blanket prerequisite of six exact serialization echoes is replaced by a separate, narrower 0.4 acceptance policy: `FORMAL_PROTOCOL_INPUT_AND_TYPED_TARGET_ONLY`. Each selected item still requires strict JSON, a closed operation schema, a complete typed target matching the unchanged exact formal oracle, source/exclusion checks and an independent model review. Any first-stage candidate that fails a gate stops the new pilot immediately; no substitute question, repair or repeated call is allowed. A deterministically contradicted 0.4 target does not consume a review call. Later prespecified comparison pairs remain fixed. Natural-language plans, rubrics, notes and native reasoning are not selected as training targets and receive no quality claim from this pilot.

The 0.4 policy adds an explicit system instruction to independently generate the required schema object, never echo the request envelope, schema or neutral syntax example. The complete body is frozen before durable consume. The original completion caps remain: DeepSeek seal/plan 4096, other DeepSeek operations 2048, Together 4096. The original maximum 44 DeepSeek plus 8 Together calls and 500,000 micro-USD reservation estimate remain unchanged. Both routes use native direct APIs; DSH schedules the bound service and does not perform model inference. A new spec, profile, source freeze, ledger and once marker are mandatory; old 0.3 state is never reopened by this worker.

Current model review is the existing fresh-context `TrainDevReviewer` with DeepSeek thinking disabled. It is not a max-effort quality judge. A future independent DeepSeek max EvalJudge for data quality and Chinese emotional expression, and a future PeerBench study, remain design work outside this pilot and budget. The Student remains Nemotron; GPT-OSS is the fixed Together comparison teacher. Student inference, training and public data publication remain unstarted and require separate authorization.
