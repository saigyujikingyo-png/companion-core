# 导师盲化视图与职责边界

版本：`MentorBlindedView/2026-10-29.3`。依据：主聊天中用户本轮直接指示。状态：`DESIGN_ACCEPTED / TEMPLATE_NOT_RUN`。

本版替代前两份模板的用途披露设计；历史文件和拒绝回执原样保留。导师，尤其 Claude，负责通用架构、方法论、各教师的笼统总纲与约束。教师产出的下游用途、学生模型及训练目的不进入导师提示或导师反馈上下文。这是职责隔离的设计，不是已经证明可以减少“能力污染”的实验结果。

## 两份记录，各有职责

| 记录 | 内容 | 接收者 |
| --- | --- | --- |
| ProjectUseRecord | 真实下游用途、用户授权、服务适用范围、来源许可、模型与程序版本、实际执行记录 | 协调器、准入检查与审计 |
| MentorView | 经核对的通用能力目标、架构约束、教师角色、粗粒度主题与阶段、已允许的汇总反馈 | 导师 |

ProjectUseRecord 不是 MentorView 的父对象序列化结果。调用器从批准过的中性简报构造独立的允许字段对象，不能把整个任务、项目历史或任意 metadata 展开到提示中。

建议 MentorView 字段：`viewVersion, briefId, capabilityGoals, architectureConstraints, teacherRoles, coarseOutline, aggregateFeedback, outputContract`。其中自由文本也要核对，字段白名单本身不能证明语义盲化。

不向导师提供：教师问答正文、逐题评分细则、学生模型及权重信息、训练/蒸馏目的、下游数据集身份、真实聊天与联想记忆、密封评测正文、旧对话或项目文件的自动注入。汇总反馈只报告允许的覆盖缺口、方法分歧、结构完整性与待解决问题，不含可反推出单题或私有样本的内容。

## 导师提示正文

```text
你担任架构与方法论导师，负责总体设计及各教师之间的分工协调。

通用能力目标：[经过核对的中性目标简报]
架构约束：[本轮相关的组件、依赖、资源和接口约束]
教师角色：[各教师的职责及边界]
已有汇总反馈：[允许分享的覆盖缺口、方法分歧和未决问题；首次可为空]

你的职责：
1. 提出通用架构与方法论，说明关键假设、依赖、适用范围和替代路线。
2. 为各教师分配粗粒度主题、阶段总纲、接口、交付结构和共同约束。
3. 设计质量检查、来源记录、分歧处理及阶段复盘的方法。
4. 根据汇总反馈调整下一轮总纲，并明确需要外部验证的事项。

请输出架构建议、教师分工总纲、共同约束、复盘标准及未决问题。
本轮不提供具体题目、答案或逐题评分细则，也不执行任何下游作业。
未提供的信息保持未知；不要将建议写成已经完成或已经验证的结果。
```

## 调用与研究边界

模型、请求档位、输入摘要哈希、允许字段版本和实际返回身份由调用器记录；提示正文不承担这些记账职责。新 MentorView 只是一种最小上下文视图，不构成服务许可，也不自动改变已有角色分类器或冻结教案。

若服务条款或明确的权限判断要求披露用途，协调器须完成该检查；不能靠字段隔离取得虚假的允许结论，不能作不实用途声明。本版不用于改写、重试或绕过已经记录的 Fable 拒绝；本轮没有新的 Claude 调用。

后续若要检验盲化的收益，另做事先冻结的对照：相同通用任务、角色和输出结构，比较架构正确性、约束覆盖、方法可迁移性与盲评结果；保留无收益和退化结果。不能把一次成功响应或拒绝率下降等同于能力改善。
