# WF2 0.6 fixed-slot wire protocol

The independent 0.5 compatibility/2 campaign successfully extracted one strict data-function response, then stopped at the original local seal validator. Authenticated fixed-stage diagnostics identified `CASES_CARDINALITY`. It produced no qualified data. That consumed run and its raw arguments remain unchanged; its output is not reinterpreted, repaired or regraded by this protocol.

`wf1-campaign/0.6` introduces a separate fixed-slot wire codec. DeepSeek's documented strict-schema subset does not enforce `minItems` or `maxItems`, so the new seal and plan schemas express their fixed cardinalities as required properties of closed objects. All substantive values still come from the independent teacher:

| Operation | Required wire slots | Locally validated representation |
|---|---|---|
| seal | `case01` through `case12` | Original 12-element Seal cases array |
| plan families | `family01` through `family16` | Original 16-element Plan families array |
| plan pairs | `pair01` through `pair08` | Original 8-element paired-family-ID array |

The wire versions are `wf2-seal-slots/1` and `wf2-plan-slots/1`. Shared `$ref` definitions avoid repeating full item schemas. Family slots 04, 08, 12 and 16 explicitly require the model's `split` field to equal `dev`; all other slots require `train`. This fixes the predeclared 3/1 first-stage and 9/3 later-stage allocation. IDs, roots, formal inputs, targets, prose and pair values are generated by the model; the host supplies no missing value or production answer. Roots remain arrays subject to the unchanged local 1..16, identifier, uniqueness and ancestry checks.

The admitted spec, operation, provider origin and consumed request binding select the codec before submission. `payloadCodec` is `WF2_FIXED_SLOTS_V1` for the DeepSeek seal/plan operations and `WF2_CANONICAL_V1` for other 0.6 operations. Endpoint, function name, full request body and schema digest remain bound before the call is consumed. A returned version cannot select a different decoder. Together comparison candidates keep the original native final-only transport and do not enter slot projection.

Projection requires the complete exact top-level and slot key sets. It rejects missing, extra, compensating extra, null, old-array and wrong-version inputs. It reads slots by their frozen names, regardless of JSON property insertion order, then maps every substantive value into the original Seal or Plan. A canonical inverse check verifies semantic preservation of the complete wire object. This is not a claim of original-byte preservation by serialization: the original arguments artifact is retained separately and never overwritten. Strings are not normalized, defaulted or repaired.

Every projected object still passes the unchanged `validateSeal` or `validatePlan`, local rational-only admission, exact rational oracle, family/root collision checks, pair binding and downstream source exclusion. Fixed slots alone do not prove independence, truth or quality. A wrong seal target still stops before planning. Any failed first-stage candidate still stops without replacement or retry. The canonical plan retained on disk is the original local representation, so later stages and cold manifest verification continue to use the same local contracts.

No call or cost allowance increases: at most 44 DeepSeek and 8 Together calls, 500,000 micro-USD reserved estimate, 16 KiB request bodies, original completion limits and deadlines. A body or response exceeding its existing limit fails rather than gaining a larger limit. The 0.3, 0.4 and current 0.5 compatibility/2 request bodies, schemas, profile digests and decoder behavior remain distinct and unchanged. A fresh 0.6 source/spec/profile, nonce, once marker and ledger are required.

The trusted parent continues to use the same `wf2-teacher-bind/2` and `wf2-teacher-inspect/2` field sets; only the spec explicitly chooses 0.6 and its profile. The approved training-root digest and strict-descendant checks remain mandatory. The actual Windows launcher keeps all new material under `D:\兴趣开发\AI\Training_0`; keys and independent authority remain outside. Core retains its portable explicit-root interface. DSH receives no material, paths or credentials.

The existing stopped-event `reason` gains only closed categories: `WIRE_DECODE`, `LOCAL_SCHEMA`, `EXACT_ORACLE`, `SOURCE`, `REVIEW`, and `UNKNOWN`. They classify allowlisted captured error codes or recorded first-stage evidence; they are not a report of every exact internal failure location. A missing target or unsupported evidence does not establish a local-schema failure and remains unknown. Authority/commit uncertainty, unknown usage and budget/time retain their existing higher-priority reasons. Neither arbitrary exception messages nor item indices, counts, hashes or body fragments enter this classification. TeacherSafeMetadata and the DSH operation protocol are unchanged, and no separate stage-persistence schema is introduced.

Synthetic checks cover all missing slots, unknown and compensating slots, old-array rejection, fixed ordering, NFD preservation, singleton splits, original local constraints, wrong targets, origin and binding mismatch, all new terminal categories, unknown usage, and the complete 51-call fixture followed by separate-process manifest verification. Existing request-body goldens cover all 42 provider/policy/operation combinations. Fixtures are not real teacher quality evidence. Actual 0.6 execution and cross-platform acceptance remain separately gated; Student inference/training and public data publication remain unstarted.

See [0.5 transport and storage policy](WF2-STRICT-DATA.md) and [control-service lifecycle](WF2-TEACHER-SERVICE.md). The [official DeepSeek strict schema guide](https://api-docs.deepseek.com/guides/tool_calls/) describes the supported schema subset; actual behavior is recorded per independent campaign.


Stable-profile follow-up: the original beta .6 first seal remained STOPPED with zero qualified data; authenticated diagnostics found native-invalid arguments before slot/local/oracle checks. The independent [stable named-data profile](WF2-NAMED-DATA.md) preserves this fixed-slot grammar, all local gates, old profile/body bytes and original negative records. It is never a fallback or regrade.
