# Hybrid profile and inference coordination

HS0/NM0 adds a bounded in-memory coordinator and text protocol. It currently has no Core live-path integration or real model backend. Declared profile identities are not authentication of loaded weights, tokenizers, processors, permissions or source contents. Author synthetic checks pass; independent code review remains pending. The [validation plan and results](HYBRID-PROFILE-PLAN.md) are the authoritative status for this slice.

`validateHybridProfile` and `profileDigest` cover model ID/revision/hash/precision, tokenizer, processor, chat template, optional adapter/router hashes, runtime build, kernel, cache layout, topology, modalities and state families. Revisions must be pinned lowercase 40- or 64-digit hex; hashes are lowercase SHA256. A hybrid declaration includes attention KV, SSM, convolution and position/prefix state. Sets are canonicalized, but source reference ordering is preserved. All records are closed own data; returned profile/binding records are deeply frozen.

`HybridBinding` includes the full tenant/subject/persona/relationship namespace, scope, generation, consent, runtime and permission epochs, session, purpose, evaluation group and ordered source revisions. Every field participates in the binding digest. The caller supplies a synchronous `validateCurrent({profileDigest,binding,phase})` and must check actual current source/permission relationships. Only literal `true` permits dispatch, delivery or completed-request replay. All other results and exceptions deny; returned rejected promises/thenables are consumed but never asynchronously grant permission. Synchronous callback reentry into coordination is rejected.

## Using the seam

Create one stable `HybridBackendLane({generate})` for each actual worker and share it across its sessions. `generate({lease,requestBytes,signal})` returns a Promise of `{contentType:'application/json',body:Uint8Array}`. There is no default endpoint, fetch, environment lookup, fallback or retry. The port receives independent request bytes and a frozen lease. A trusted port must faithfully implement the declared worker identity; these types do not verify it.

The port is trusted in-process code, and this coordinator is not a sandbox for arbitrary injected JavaScript or damaged Promise internals. Supported ports return an ordinary native Promise with stable native `constructor`/`Symbol.species`; the real mapper must establish that Promise and its own underlying-work rejection cleanup before returning. An own `then` decoration is supported because the coordinator uses the intrinsic observer. Normal rejection, rejection after local abort and a backend that ignores abort are handled by the coordinator once this observer is installed. Real mapper integration remains `PENDING_OWNER`.

A throwing or otherwise invalid constructor/species is a port protocol violation. If observer installation fails, the public request becomes `HYBRID_BACKEND_UNOBSERVABLE`/UNKNOWN and the physical permit stays held. The coordinator does not claim to have installed a rejection handler or made that violating Promise's later rejection safe. It avoids actively aborting that unobservable request, but this does not protect against an independent late rejection; cleanup is the violating port's responsibility. Close, rebind and a later unobserved outcome cannot release that permit or authorize retry. The rejection-consumption guarantee is therefore limited to supported port promises, rather than the unqualified late-result wording in the original contract. The constructor-violation fixture's late-rejection cleanup is deliberately installed by the fixture port before poisoning, and is not evidence of coordinator protection for arbitrary Promise violations.

Create `HybridInferenceSession({lane,profile,binding,validateCurrent,timeoutMs?})`, then call `propose({requestId,selectedEvidence,signal?})`. Predispatch failures can throw synchronously; after consumption the result is a Promise. Use `asInferenceAdapter(requestId)` for the existing `InferenceAdapter` API. This bridge prebinds a stable request ID and the original lease; after rebind, make a new bridge with a legitimately new request ID. It advertises text only, validated structured output and local-drop-only cancellation. Image/video declarations in a profile do not widen that capability.

Evidence must be an ordered array of 1–16 valid existing `Evidence` objects and match the number of `binding.sourceRefs`. Each position refers to the source at that position. Evidence has no source ID of its own, so the coordinator cannot infer or prove that a text belongs to a source or detect a caller's semantic swap; the trusted selector and currentness validator own that association. Unknown media, tool and attachment fields are rejected before backend dispatch. Proposal validation reuses the existing final wire semantics.

`companion-hybrid-json-v1` is a project-owned normalization protocol, not a NVIDIA/vLLM HTTP compatibility claim. Requests contain version, memory-proposal kind, request ID, complete lease, profile digest, binding and selected evidence. Responses contain version, final-proposal kind, exact request ID/lease/profile digest and one valid Proposal. Invalid UTF-8, JSON, stamps, draft/reasoning/tool/audio fields, extra fields or oversized bodies fail closed. Bodies are copied when received; arbitrary mutation before the port hands off its result cannot be prevented by a consumer. No body or hidden reasoning is logged.

## Consumption, cancellation and limits

The shared lane records each request synchronously before invoking the port. It retains at most 64 lifetime IDs and reserves at most 2 MiB of controlled UTF-8 metadata plus Proposal storage across all sessions. Each new entry reserves the full 16 KiB result allowance and bounded metadata. Prompt bytes are represented by a digest of the complete canonical request, including the original lease, profile, binding and evidence; plaintext prompts are not retained in the ledger. With this metadata representation the ID cap is reached before the byte cap; neither can be increased by the caller.

An identical completed request in its original current lease replays an independent Proposal after currentness validation. Identical in-flight or UNKNOWN requests never redispatch; differing payloads/leases conflict. Another session or another namespace receives only a generic conflict, and `status(requestId)` returns `null` for records it does not own. Status exposes bounded technical state only, never cached Proposal or binding. Rebind changes every logical lease even when all declarations are identical.

There is one physical request at a time and no queue. For supported port promises, abort or timeout ends the public result promptly but keeps the worker permit until the original Promise really settles. Late rejection is handled; late success cannot promote UNKNOWN to completed. Backend synchronous throw, rejection, timeout, abort, malformed output and stale permissions all conservatively retain UNKNOWN after dispatch. A failed dispatch gate consumes no ID; a failed replay gate leaves the completed record intact while withholding the Proposal.

`invalidate(reason)`, `close()` and `requireStateCapability('reset')` fence local leases and abort their signals without requiring free ledger capacity. Their receipt always says `logicalFenced:true, backendStopConfirmed:false`. Close is irreversible. Rebind validates replacement declarations before fencing the old lease; malformed replacements leave the original lease intact. Cleanup and old-ID status remain available at full capacity. None of these operations removes records or byte reservations.

Profile and binding are each bounded to 8 KiB, request/reply each to 64 KiB, sources/evidence each to 16. IDs are 1–128 UTF-8 bytes without control characters; generation fields are nonnegative safe integers and source revisions are positive. Timeout defaults to 10 seconds and is restricted to 1–30,000 ms. These byte limits do not measure tokens, context length, GPU memory or model throughput.

## Explicitly unimplemented

`prefixReuse`, `checkpoint`, `fork`, `rollback`, `transfer` and `tensorExport` always reject with `HYBRID_STATE_UNSUPPORTED`. Reset is only a logical fence. No metadata result proves tensor destruction, physical cancellation, worker unload, state restoration or weight forgetting. There is no image encoding, vision token expansion or loss mask implementation.

The lane is RAM bookkeeping, with durable cross-process dedupe `NOT_SUPPORTED` and real Core wiring `PENDING_OWNER`. The trusted worker owner must preserve lane identity and continue to enforce existing persistent Safety/request consumption. Creating a new lane or restarting a process is not permission to clear UNKNOWN or retry. No metadata import/restore interface exists.

The source rationale for including all hybrid state identities is the pinned [Nemotron super35 architecture](https://github.com/NVIDIA-NeMo/Nemotron/blob/a8900c8dc4df1aecb07a6855e0f0f0dc0cc7e625/docs/nemotron/super35/README.md) and [separate KV/SSM/convolution precision and cache description](https://github.com/NVIDIA-NeMo/Nemotron/blob/a8900c8dc4df1aecb07a6855e0f0f0dc0cc7e625/docs/nemotron/super35/quantization.md). These were accepted source-only inputs. This slice does not run their code or transfer their performance/quality claims. Synthetic coordination, source identity, real service compatibility, hardware capacity and model quality remain separate acceptance layers.

## Local validation (2026-10-28)

The accepted local implementation passed the original 18 synthetic fixtures; the final inference boundary delta passed 11/11 and targeted strict TypeScript. An independent complete-project TypeScript check also exited 0. These are separate source-bound runs and are not added together. The same independent max reviewer closed both P2 findings. The supported port returns an ordinary native Promise with stable constructor/species and owns underlying-work rejection cleanup; this does not establish arbitrary damaged-Promise safety. Real model mapping, tensor operations and persistent Core integration remain unimplemented. CI for the published head is pending.
