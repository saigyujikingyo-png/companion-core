# WF0 metadata contracts

WF0 is an independent, bounded TypeScript declaration validator. It does not generate, read, score or edit teaching content. There is no provider client, trainer, Store integration, database migration or new dependency. Existing curation v1, TJ0/TJ1 and their evidence remain unchanged.

The schema names end in `/0.1`: `TeacherCapabilityRecord`, `SourceLicenseRecord`, `TeachingPlan`, `QuestionPolicy`, `CandidateRecord`, `FamilySplitRegistry`, `TeachingBundle` and `TeachingTrustSnapshot`. Plan and policy fields contain opaque references and limits, not concrete curricula, questions, answers, rubric, rewards or filters. The small question-node structure records reference relationships only. Fixtures are original synthetic metadata; they contain no training examples or sealed test content.

## Interfaces and meaning

`src/teaching-validation.ts` exports `validateTeacherCapability`, `validateSourceLicense`, `validateTeachingPlan`, `validateQuestionPolicy`, `validateCandidate`, `validateFamilySplit`, `checkTeachingRoleAccess`, `checkTeachingAdmission` and `exportTeachingManifest`. Validators accept JSON text or trusted in-process data objects and return detached, deeply frozen snapshots. External inputs must use the bounded `parseTeachingJson` profile in `src/teaching-json.ts`; it rejects duplicate decoded keys, unknown prototype keys, invalid Unicode, nonfinite/fractional/negative/unsafe integers and negative zero. Object inputs reject getters without invoking them, unusual prototypes, cycles, sparse arrays and non-data properties. JavaScript proxies are outside this trusted in-process boundary.

The JSON numeric lexical profile is exactly `0|[1-9][0-9]*`, followed by the safe-integer range check. Negative signs, decimal points and exponents are rejected **before** conversion to a JavaScript number, even when `1.0` or `1e0` would have an integer value. This also rejects underflow such as `1e-400` and fractions that would round to integers. Pass external JSON text directly: pre-parsing it with `JSON.parse` loses the original spelling and cannot preserve this lexical guarantee. The trusted object API checks the numeric value it actually receives.

Every accepted result is `DECLARATION_VALID_ONLY`. Admission reports may say `ELIGIBLE_METADATA`, but always retain `execution: NOT_AUTHORIZED`, `quality: NOT_EVALUATED`, `rightsAuthenticity: NOT_AUTHENTICATED` and `semanticLeakage: NOT_EVALUATED`. No token, permit, job, API request or training capability is created. Empty and rejected datasets retain these limitations.

The second argument to `checkTeachingAdmission(bundle, currentTrustSnapshot)` and the exporter is supplied separately by the host. It binds the current authority ID, revision and runtime ID, current time, roles, use-specific rights decisions and observed inference receipts. This separation is a **host trust assumption**, not authentication of the snapshot. A caller able to forge both inputs can forge matching declarations; JSON, hashes, role labels and signatures are not proof of legal rights or actual inference. A later trusted authority/storage integration must obtain and recheck real evidence before any real phase.

TeachingCoordinator identity must match the separately supplied role and decision. Required uses are `coordinate`, `generate`, `train` and, for public material, `publish`. Sources require `generate`, `train` and public `publish`; `UNKNOWN`, `DENY`, mismatched subjects/digests and expired decisions refuse metadata eligibility. No provider is hardcoded as allowed. Requested model ID, returned alias and immutable revision remain separate; absent revision/evidence stays `null` (unknown). Capability `ACCEPTED` is itself a declaration, not a probe result produced by WF0.

ResearchMentor can access only operational metadata under the pure role classifier. It cannot enter the coordinator role or receive teaching content, student answers, per-item feedback or sealed content. This classifier performs no I/O and does not install operating-system ACLs. It does not give other roles unrestricted access: actual material permissions remain the host's responsibility.

An `actual` question-node answer must match a separately supplied observed inference receipt on receipt ID/digest, candidate/node, question/answer digest, student snapshot, current authority, runner role and observed time. The observation lies between plan creation and candidate metadata finalization. A synthetic answer cannot carry an actual receipt. This verifies consistent declarations only, not that the inference happened. Synthetic input data and actual inference execution are separate concepts.

## Source families, privacy and freezing

The supplied family registry must include the full relevant ancestry, including rejected/discarded bridge nodes and sources outside the current candidate page. All parent edges, repeated family IDs and known equal content digests participate in connected-component checks **before candidate deduplication**. Missing ancestors, cycles, conflicting family labels and train/dev/calibration/sealed split conflicts reject the whole input. Equal known digests across public/private nodes are rejected too. Quarantined ancestors refuse eligible descendants. Public descendants of private nodes are rejected; private descendants of public sources are allowed but stay private. A source digest may be `null` (unknown); selected candidate nodes must bind their exact declared content digest. Unknown or dishonestly declared digests cannot establish absence of duplication.

Candidate `parentCandidateIds` lists all candidate ancestors recorded in its registry lineage, not only immediate parents. Candidate IDs, source node IDs and family declarations must match. Identical candidate ID plus identical canonical metadata has one effect; the same ID with changed metadata is a conflict. Reusing a content digest under another candidate ID is conservatively rejected, including across split, public/private or rejected records. This exact-digest rule cannot detect hidden semantic copies or a dishonest digest. The validator does not inspect referenced bytes.

Candidate `createdAt` means metadata finalization, not a preallocated inference intent. The declared lifecycle is plan creation, then inference observation when applicable, candidate finalization, registry freeze containing the known fingerprints, bundle creation, then current inspection (equality at boundaries is allowed). This final registry freeze is **not** the earlier sealed-evaluation-suite seal; proof that a sealed suite existed before generation remains a separate custodian requirement, not implemented here. Epoch/runtime mismatch, future metadata and expired source/plan/teacher declarations refuse the current check. The caller supplies trustworthy current time; a pure stateless function cannot detect an attacker replaying both an old bundle and an old trust snapshot. The exporter revalidates both inputs on every call. There is no persistent capability to restore, and no self-authenticating freeze.

Whole-dataset isolation depends on the host providing the complete registry and performing cross-batch reconciliation. WF0 does not implement a global data lake, discover omitted source edges, verify near-duplicates, or enforce custodian mounts. Splitting calls cannot legitimately omit cross-batch ancestry. Independent sealed evaluation custody, ACLs, backups, logs and contamination checks remain separate work.

## Export and bounds

`exportTeachingManifest` is a deterministic **public metadata-only** exporter. It returns canonical JSON, SHA-256 of that public projection and byte length, with candidate IDs, public content references, split and declared sizes. It omits questions, answers, inference receipts, rights documents and the family registry itself. It does not export a full bundle/registry digest: changing an unrelated sealed/private registry component does not change the public projection or its digest. The export is therefore not an authenticated binding to a full private freeze. Any private bundle is refused; a private manifest/storage API is not implemented. Callers must not relabel confidential identifiers as public. The module never reads a referenced asset or path.

Limits are fixed in `TEACHING_LIMITS`: input JSON 1 MiB, depth 24, 65,536 JSON nodes, 256 UTF-16 units per string; individual small records 64 KiB; at most 128 input candidates, 2,048 registry nodes and 8,192 edges; question trees at most 16 nodes, depth 8, 2 children per node and 8 actual answers; output at most 2 MiB. IDs are restricted opaque identifiers, not paths or URLs. All metadata counts are safe nonnegative integers. Candidate declared payload size is at most 64 KiB and declared tokens at most 32,768; these are **declarations only**.

Actual message/text/media byte, tokenization, loss-mask, pixel/frame, decoding-memory and semantic validations are **NOT_IMPLEMENTED**. The research WF0-07 content/media boundary specification is only partially implemented at metadata/tree limits; no full WF0-07 content acceptance is claimed. Policy token/call limits are recorded, not consumed by a runner. No training/export/reload/quality or real permission acceptance is implied.

This slice does not parse provider streams or distinguish an observed reasoning-only stream from a completed final answer. A later teacher adapter must preserve native reasoning and final outputs as separate references with provenance; reasoning is not proof of internal computation or answer correctness, and length/reasoning alone is not final-answer success. Generic model IDs can describe a text teacher such as GPT-OSS without implying that its Together service has been called or admitted.

Focused verification uses `node --test test/teaching-validation.test.ts` and strict `tsc --noEmit`. Independent review, whole-suite integration and cross-platform CI are separate evidence layers; this document does not predeclare them passed.
