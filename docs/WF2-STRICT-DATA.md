# WF2 rational data-function pilot

`wf1-campaign/0.5` is a new, bounded research campaign. It retains the original 44 DeepSeek / 8 Together call ceilings, 500,000 micro-USD reservation estimate, completion caps, deadlines, first-four gate, independent teacher roles, source exclusion and exact local oracle. It does not retry a consumed 0.3 or 0.4 run. The original format profile/1 and profile/2 remain `NOT_PASSED`, and the actual 0.4 first-seal JSON failure remains unchanged. There is no third serialization probe or output repair.

The 0.5 domain is only `rational.evaluate.v1`. Local seal and plan admission, later plan reads and cold manifest verification reject every other verifier, including otherwise valid JSON Pointer inputs. The model independently generates all substantive plans, sealed cases, answers and rubrics. Host-authored material specifies the protocol and schema; it supplies no production teaching example or answer.

DeepSeek uses the fixed `https://api.deepseek.com/beta/chat/completions` endpoint with thinking disabled, one named function, `strict: true`, and the same function in `tool_choice`. The function is an inert data carrier. The full closed schema appears once in `tools[0].function.parameters`; the user message carries only operation data, role and serialization constraints. The old broad schema is not forwarded, and the catalog includes only the rational domain. The body remains at most 16 KiB.

The remote schema uses closed objects with all properties required, `enum`, `anyOf`, recursive `$ref` / `$def`, and canonical decimal-string patterns. Unsupported string/array length keywords are not sent. Local checks still enforce exactly 12 sealed cases, 16 plan families, 8 distinct paired families, fixed 3/1 and 9/3 train/dev splits, unique roots and formal fingerprints, UTF-8 sizes, AST depth 6 / nodes 31, 128-bit leaf integers, positive denominators, 4096-bit intermediate values, division validity and exact reduced targets. A target may exceed 128 bits when the supported expression produces it; the leaf bound is not incorrectly applied to the result. Provider-side schema enforcement cannot grant local acceptance.

Only `finish_reason: "tool_calls"`, exactly one call to the consumed function name, string `arguments`, and null or empty assistant `content` enter the decoder. The call requires `id`, `type` and `function`; response compatibility version `wf2-strict-data-response/2` additionally permits an optional `index` only when it is the integer zero. Other indices, types and unknown fields are rejected before the arguments sink. Mixed content, multiple or wrong functions, a different finish reason, invalid JSON, duplicate keys and refusal remain rejected. The original arguments string is retained separately as `strict-tool-arguments`, with `payloadOrigin: STRICT_TOOL_ARGUMENTS`; it is never relabeled as a native final. The function is never executed, and no tool-result message, second model round trip, fallback, extraction, normalization or repair occurs. Together keeps its fixed native JSON final-only endpoint and codec, with `payloadOrigin: NATIVE_FINAL`.

Before durable consume, the request body and an explicit binding freeze the provider endpoint, codec, function name and schema digest. Submission validates this contract again before touching transport. Usage that is absent or exceeds reservation blocks subsequent calls. A structural or formal failure in the first four candidates stops immediately without replacement or review of an already contradicted target. The first seal is itself a strict structural and exact-oracle gate before any plan or candidate call. Passing this pilot would establish only `FORMAL_PROTOCOL_INPUT_AND_TYPED_TARGET_ONLY` acceptance for its recorded items; natural-language quality, reasoning quality and general Unicode fidelity remain outside the claim.

The official [DeepSeek tool-call guide](https://api-docs.deepseek.com/guides/tool_calls/) documents beta strict schemas and their supported subset. The [chat completion API](https://api-docs.deepseek.com/api/create-chat-completion/) documents named tool selection for non-thinking mode and the tool-call response shape. Those documents motivate the explicit new transport; they are not evidence that a particular actual campaign passed.

## Portable storage binding

The trusted 0.5 bootstrap is `wf2-teacher-bind/2`. Its closed fields are `version`, `approvedTrainingRoot`, `runtimeRoot`, `authorityPath`, `expectedHead`, `spec`, `custodyKeyBase64`, `objective`, `credentials`, and `capability`. The 0.5 spec adds `storageBindingDigest`. The independent read-only bootstrap is `wf2-teacher-inspect/2` with `version`, `approvedTrainingRoot`, `runtimeRoot`, `authorityPath`, `expectedHead`, `spec`, and `custodyKeyBase64`; it accepts no provider credentials or objective. The old explicit bind/1 and inspect/1 remain 0.4 only, and the legacy worker remains 0.3 only. Retained runs use their archived source and never upgrade implicitly.

Both roots must already exist as canonical private directories. The runtime must be a strict descendant of the approved root: equality, prefix siblings, aliases and escaping paths are refused. `bindTrainingRoot` returns their real paths and SHA256 of UTF-8 canonical JSON for `{version:"wf2-training-root/1", approvedTrainingRoot, runtimeRoot}`. The spec binds that digest. Admission verifies it before ledger or artifact writes; artifact reads/writes, send/settle boundaries and cold inspection recheck it. The separate authority directory must be canonical and outside the entire approved training root. Core has no default root, environment discovery or fallback location.

For the user's Windows deployment, the dedicated Sol launcher fixes the approved root to `D:\兴趣开发\AI\Training_0` and provisions one new child directory per campaign. All request/raw/candidate/clean/train/dev/sealed/manifest/tokenized material belongs under that root. Existing failed C-drive originals remain untouched. Provider secrets, DPAPI material and independent authority remain outside the training tree; C may hold code and content-free operational metadata. Paths, credentials and the private bootstrap never enter the DSH control plane. Cross-platform synthetic tests use explicit private TEMP roots rather than a hard-coded drive.

Cold inspection authenticates the ledger/spec/head and storage binding without provider calls or automatic recovery. Failed or revoked campaigns expose recorded counts only and never read a manifest. A completed, retained campaign may internally read its train plan and manifest, verify every formal target, plan family/roots/split, source/exclusion evidence and unique projection, and return only counts/enums. It never reads sealed artifacts or exposes content/refs. Invoice status remains `UNKNOWN`; reserved and known-usage estimates are separate.

## Validation boundary

The first actual 0.5 campaign stopped at the seal response before parsing its arguments. Authenticated structural diagnostics established HTTP 200, one named tool call, empty assistant content and an additional `index: 0` field. The original closed decoder rejected that field with `WF1_FIELDS` before reaching its argument callback. This establishes a transport compatibility defect, not a failure of the mathematical oracle or proof that the arguments are valid. The original failed campaign and source remain retained, with no regrade, extraction or replay. The response compatibility change produces a new profile digest for a separate campaign; all 42 synthetic request bodies spanning the three policies, two providers and seven operations retain their pre-fix byte hashes. No request prompt, schema, budget, storage boundary or local acceptance gate changes.

The separate compatibility/2 actual campaign crossed response extraction but stopped at local seal validation. Authenticated fixed-stage diagnostics identified `CASES_CARDINALITY`; no qualified data resulted. Its arguments are not repaired or re-evaluated. The separately versioned [0.6 fixed-slot wire protocol](WF2-FIXED-SLOTS.md) addresses the representable cardinality requirement while retaining this 0.5 implementation and its failed records unchanged.

Author focused checks exercise the new codec's rejection cases, unchanged old final-only semantics and body goldens, storage rejection before writes, consumed route/body binding, rational-only admission, unknown usage, first-four stop, and a 51-call entirely synthetic loop followed by another process's read-only manifest verification. They are zero-API fixtures, not independent teacher quality evidence. Native DSH rc3 dual-child lifecycle acceptance is retained separately; 0.5 actual API/data acceptance and rc2 three-platform CI require their own results.

The existing disabled-thinking `TrainDevReviewer` remains the current independent model review role. The proposed DeepSeek max EvalJudge for Chinese emotional quality and later PeerBench work are not implemented by this change or included in this budget. Student Nemotron inference/training and public data publication remain unstarted and require separate authorization.
