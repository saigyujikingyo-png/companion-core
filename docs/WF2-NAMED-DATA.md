## Bounded response diagnostics

`ProviderResult.responseFailureCode` contains only the source-owned enum in `wf2-response-diagnostic.ts`, persisted with the existing authenticated observed-response transaction. Parameter strict-parser failures retain scoped `ARGUMENTS_WF1_*` codes. Only on that rejection path, one native `JSON.parse` of the same already bounded in-memory argument string is used for diagnosis: its value is discarded, `SyntaxError` yields `ARGUMENTS_NATIVE_JSON_INVALID`, other errors yield `UNKNOWN`. It never contributes a replacement value or acceptance. A native-valid duplicate key, numeric-profile violation or long token remains rejected by the original strict parser. Root-not-object, tool/envelope rejection and actual artifact `put` failure have distinct codes. A failed `put` remains `ARTIFACT_WRITE_FAILED` even when its exception happens to carry a parser-like code. Exception messages, references, paths and payload excerpts never enter the projection.

The new stopped event is `wf2-worker-event/2` with exactly `version,type,reason,responseFailureCode,metadata`. All other worker events, control messages, DSH operations and TeacherSafeMetadata remain unchanged. The production binder projects reason, metadata and the latest attempt's response code from one fresh authenticated snapshot. A latest pending attempt, absent old code, stale authority/head or half commit yields `UNKNOWN`; it never searches back for a previous failure. The code describes the latest settled response, not the whole campaign's root cause or every earlier candidate.

The bridge saves the validated negative snapshot before owner withdrawal and returns `wf2-teacher-bridge/2` with the existing fields plus non-null `responseFailureCode`. Successful completion ACK does not carry a response diagnosis, so its bridge code is `UNKNOWN`, not an invented `NONE`. A saved negative snapshot remains explicitly `RECORDED_TERMINAL_SNAPSHOT_NOT_LIVE` after closing. Cold inspection success and refusal both use `wf2-teacher-inspection/2`; success adds the same pure latest-attempt projection under `RECORDED_CLAIMS_ONLY`, including authenticated revoked history. Refusal always uses `UNKNOWN`. Cold inspection still makes no provider call, never resumes a consumed run, and never reads sealed content.

Author synthetic checks, independent review, actual new campaign and cross-platform CI remain separate evidence. Actual stable API execution, training and publication require their own authorization; this source change does not grant them.
